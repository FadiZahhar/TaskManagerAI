# ADR-001: Use FastAPI for the Module 1 Task Tracker API skeleton

**Decision:** The Task Tracker REST API will start as a minimal Python FastAPI application with a single `GET /health` endpoint, automatic Swagger documentation at `/docs`, and no task CRUD, authentication, user accounts, external production database, Docker, cloud deployment, or frontend in Module 1. FastAPI is selected because it provides a lightweight path to a locally runnable REST API, supports type-hinted request and response models for future task schemas, and exposes interactive API documentation with minimal configuration. This decision keeps the first module focused on reviewed requirements, an architecture choice, and a verifiable local skeleton while leaving persistence, task CRUD routes, validation models, and deployment concerns for later modules. The tradeoff is that the Module 1 application is intentionally not feature-complete; it proves the service boundary and development workflow rather than implementing the full product.
