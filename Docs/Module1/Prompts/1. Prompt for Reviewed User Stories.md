You are a senior backend product engineer helping define requirements for a small learning project.

Context:
I am building a Task Tracker REST API using Python and FastAPI for Module 1.
The final app will eventually support create, view, update, delete, filter, and status movement for tasks.
Each task has id, title, description, status, priority, and assignee.

Scope:
Included:
- Create, view, update, and delete tasks.
- Filter tasks by status and priority.
- Validate task data.
- Swagger API docs through FastAPI.

Excluded:
- Authentication.
- User accounts.
- Multi-tenancy.
- Real-time updates.
- Mobile app.
- Notifications.
- Production database.
- Deployment.
- Frontend.
- Full implementation in Module 1.

Task:
Generate 8 user stories for the Task Tracker API.

Constraints:
- Each story must be buildable and testable.
- Each story must include acceptance criteria.
- Include validation edge cases.
- Include missing task behavior.
- Include invalid status and invalid priority behavior.
- Include the rule that a task in Done cannot move back to ToDo or InProgress.
- Do not add authentication, users, admin roles, teams, billing, frontend, Docker, or deployment.
- Keep the stories appropriate for a small learning project.

Output format:
Return a markdown table with these columns:
1. ID
2. User Story
3. Acceptance Criteria
4. Notes / Edge Cases
