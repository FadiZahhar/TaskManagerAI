Here's a minimal, runnable verification checklist for the Module 1 skeleton. Run everything from inside the project root (`task-tracker-module1/`).

## Step 0 — Create and activate the virtual environment

**Command**
```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
```
**Expected:** your shell prompt is now prefixed with `(.venv)`.
**If it fails:** confirm Python 3.11+ with `python3 --version`. On Windows use the PowerShell/cmd activation path above. If `venv` is missing on Linux, install it (`sudo apt install python3-venv`).

## Step 1 — Dependencies install successfully

**Command**
```bash
pip install -r requirements.txt
```
**Expected:** ends with `Successfully installed fastapi… uvicorn… httpx… pytest…` and no error lines.
**If it fails:** check you're in the activated venv and in the project root (the folder containing `requirements.txt`). Upgrade pip (`pip install --upgrade pip`) and retry. Read the last error line — a build/network failure names the offending package.

## Step 2 — Pytest test suite passes

**Command**
```bash
pytest
```
**Expected:** `2 passed` (the `/health` 200/status test and the timestamp test), exit code 0.
**If it fails:** run `pytest -v` to see which test failed. A `ModuleNotFoundError: No module named 'app'` means you're not in the project root — `cd` there and rerun. An `httpx`/TestClient error means Step 1 didn't complete; reinstall.

## Step 3 — Uvicorn starts the app

**Command**
```bash
uvicorn app.main:app --reload
```
**Expected:** log lines including `Uvicorn running on http://127.0.0.1:8000` and `Application startup complete`. Leave this terminal running.
**If it fails:** `Error loading ASGI app` usually means wrong path (must be `app.main:app`) or wrong directory. If port 8000 is busy (`address already in use`), start on another port: `uvicorn app.main:app --reload --port 8001` (adjust the URLs below accordingly).

## Steps 4–6 — GET /health returns 200, `status="ok"`, and a timestamp

**Command** (in a second terminal, venv not required here)
```bash
curl -i http://127.0.0.1:8000/health
```
**Expected:** first line `HTTP/1.1 200 OK`; body is JSON like `{"status":"ok","timestamp":"2026-07-06T…+00:00"}`. Confirm all three: status line is 200, `status` equals `ok`, and a `timestamp` field is present.
**If it fails:** `connection refused` → the server (Step 3) isn't running or you used the wrong port. A 404 → the route isn't registered; confirm `app.include_router(health.router)` is in `app/main.py`. Missing `timestamp` → check `app/api/routes/health.py` builds the response with `datetime.now(timezone.utc).isoformat()`.

Optional one-liner that pretty-prints just the body:
```bash
curl -s http://127.0.0.1:8000/health | python3 -m json.tool
```

## Step 7 — /docs loads in the browser

**Command:** open in a browser:
```
http://127.0.0.1:8000/docs
```
Or verify headless:
```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/docs
```
**Expected:** the Swagger UI renders and lists the `GET /health` endpoint under the *System* tag; the headless check prints `200`.
**If it fails:** confirm the server is running and the port matches. If the page is blank, hard-refresh; also check `http://127.0.0.1:8000/openapi.json` returns JSON (that's what Swagger consumes).

## Step 8 — No out-of-scope features were added

**Command** (from the project root; stop the server first with Ctrl+C, or use a new terminal)
```bash
grep -riE "sqlalchemy|sqlmodel|sqlite|databases?|psycopg|oauth|jwt|passlib|login|docker|dockerfile|react|vue|@app\.(post|put|patch|delete)" \
  app tests requirements.txt --include='*.py' --include='*.txt' ; \
echo "exit=$?"
```
Also eyeball the tree:
```bash
find . -type f -not -path '*/.venv/*' -not -path '*/__pycache__/*' | sort
```
**Expected:** grep prints nothing and reports `exit=1` (grep returns 1 when there are no matches — that's the pass condition here). The file list shows only the 13 skeleton files, with no `Dockerfile`, no database/auth modules, and no CRUD route decorators.
**If it fails:** grep printing a match means an out-of-scope dependency or route sneaked in — open the named file and remove it. Any `POST/PUT/PATCH/DELETE` decorator or a `Dockerfile`/frontend file should not exist in Module 1.
