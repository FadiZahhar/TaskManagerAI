11. Common mistakes to avoid

The document is designed to prevent these exact issues:

1. Asking Claude to build the whole backend at once.
2. Letting Claude create a second FastAPI() instance.
3. Using Pydantic v1 syntax like @validator, class Config, or .dict().
4. Adding SQLAlchemy or a database when Module 2 requires in-memory storage only.
5. Allowing clients to submit id, created_at, or updated_at.
6. Returning 200 instead of 201 for POST /tasks.
7. Returning 404 for an empty task list.
8. Returning JSON for successful DELETE instead of empty 204.
9. Adding transition validation too early.
10. Validating only the new status instead of the (current, new) status pair.
11. Breaking title-only PATCH by forcing transition validation when payload.status is absent.
12. Editing tests just to make them pass.
13. Skipping the Break Test.
14. Writing a reflection without verification evidence.
