# Reflection

I treated this project as a human-owned workflow that used AI for specific steps, not as a generator of the whole solution. I used Claude Code to inspect the real repository — `app/models.py`, `app/storage.py`, `app/main.py`, and the single-file `frontend/index.html` — and to summarize the existing task API, enums, and Kanban rendering before proposing where the two features would fit. I then drove focused, phase-by-phase prompts: plan, backend, pytest, frontend, verification, a Break Test, and one narrow refactor per feature. Alongside Claude I ran pytest for automated checks and drove a real headless Chrome browser over the DevTools Protocol to observe the UI and capture actual request URLs, because no browser tool was otherwise available.

AI helped most in design and adversarial review. Before writing Feature 2 I fanned out several review perspectives that produced a concrete test matrix and edge cases — whitespace-only search, a null assignee, regex metacharacters, and never sending `overdue=false`. The value was the reasoning and the cases, not only the code; I still reviewed each diff, ran the smallest relevant test, then the full suite before keeping anything. That process surfaced a real hardening point — trimming a stored assignee value — which I accepted.

AI also proposed weak defaults I rejected. Left unconstrained it assumed a required timestamp with a stored `overdue` boolean for due dates, and client-only JavaScript filtering for search. Both would have violated the brief, so I corrected the prompts with repository facts and required an optional date-only field with a derived overdue rule, and server-side filtering with tests. Several browser "failures" during verification turned out to be bugs in my own test harness — a repaint race, a mis-seeded date, a `null` sentinel matched by a regex — which I diagnosed from the captured DOM and fixed in the harness, never in the application.

My review materially changed outcomes: I insisted empty filter selects omit their parameter rather than send an empty enum that would 422, and I pinned the strict "due today is not overdue" boundary. The four Break Tests were the strongest evidence — each passed on correct source, failed after one temporary mutation for the exact semantic reason, and passed again after restoration, with a clean Git state. That gave me more confidence than a green suite alone. The lesson is that AI-assisted coding is a controlled feedback loop: define observable behavior, supply real context, inspect the output, test the smallest change, and document the human decision.
